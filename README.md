# sudohapgen

`sudohapgen` is a Nextflow workflow for generating **pseudo-haplotypes from BAM files**, designed for **low-coverage and ancient DNA (aDNA)** datasets.

The pipeline uses `samtools` and `ANGSD` to sample a single allele per site, producing haploid genotype representations suitable for downstream population genetics analyses such as PCA, ADMIXTURE, and f-statistics.

---

## Overview

Ancient DNA data is typically low coverage, making diploid genotype calling unreliable. Instead, pseudo-haploid genotypes are generated by sampling one allele per site.

`sudohapgen` automates this process:

1. Splits BAM files by chromosome
2. Indexes chromosome-specific BAMs
3. Filters reads
4. Samples alleles at predefined sites using ANGSD
5. Converts output into haplotype-like format

---

## Workflow
BAM → Chromosome split → Index → ANGSD (dohaplo) → haplotoplink → Results + MultiQC

## Installation

### Requirements

- Nextflow (>=22.x recommended)
- Conda/Mamba (recommended profile)

### Run with Mamba profile

```bash
nextflow run popgen48-sudohapgen/ --input input.csv --outdir first_run -profile mamba -resume --include_chroms include_chroms.txt --sites_file sites.csv
```

## Input files

The pipeline requires three main input files: a sample sheet, a sites mapping file, and optionally a chromosome list.

### 1. Sample sheet (`--input`)

A CSV file describing the BAM files to process.

**Required columns:**

- `sample` — unique sample identifier
- `bam` — path to the BAM file
- `idx` — path to the BAM index file (`.bai`)

**Example:**

```csv
sample,bam,idx
sg55_t,/data/.../lib1_rmdup.bam,/data/.../lib1_rmdup.bam.bai
```

### Sites mapping file (`--sites_file`)

The `sites_file` defines which genomic sites will be used for pseudo-haplotype generation and links each chromosome to its corresponding ANGSD-indexed sites files.

#### Format

A CSV file with the following columns:

- `chrom` — chromosome name
- `file_path` — path to a directory containing ANGSD sites files

#### Example

```csv
chrom,file_path
1,/data/.../chrom_1/
2,/data/.../chrom_2/
```
Each file_path must point to a directory containing ANGSD-indexed sites files:
```csv
chrom_1_sites.txt
chrom_1_sites.txt.bin
chrom_1_sites.txt.idx
```

## Parameters and options

The following parameters control the behavior of the pipeline.

---

### Required parameters

| Parameter | Description |
|----------|------------|
| `--input` | Path to the sample sheet CSV file |
| `--outdir` | Output directory where results will be written |
| `--sites_file` | CSV file mapping chromosomes to ANGSD-indexed sites directories |

---

### Optional parameters

| Parameter | Default | Description |
|----------|--------|------------|
| `--include_chroms` | `null` | Text file listing chromosomes to process. If not provided, chromosomes are inferred using `samtools idxstats` |
| `--min_aln_readlen` | `30` | Minimum aligned read length. Reads shorter than this are excluded |
| `--min_mapq` | `20` | Minimum mapping quality (MAPQ). Reads below this threshold are filtered out |
| `--min_baseq` | `20` | Minimum base quality. Bases below this threshold are ignored |
| `--min_depth` | `1` | Minimum read depth required at a site to perform allele sampling |
| `--n_basetrim` | `5` | Number of bases trimmed from each end of reads to reduce damage effects |

---

### Filtering behavior

The following filters are applied before pseudo-haplotype generation:

- Reads must meet:
  - minimum length (`--min_aln_readlen`)
  - minimum mapping quality (`--min_mapq`)

- Bases must meet:
  - minimum base quality (`--min_baseq`)
  - trimming of `--n_basetrim` bases from both ends

- Sites must have:
  - at least `--min_depth` reads

---

### Notes

- Default values are chosen to be suitable for **ancient DNA datasets**
- Parameters can be adjusted depending on:
  - sequencing quality
  - coverage depth
  - downstream analysis requirements
- Overly strict filtering may reduce the number of usable sites
- Too lenient filtering may introduce noise or damage-related biases
